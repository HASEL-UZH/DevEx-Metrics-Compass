# DX-Metrics-Compass

Interactive dashboard for navigating developer experience (DevEx) metrics across research and industry.

## Stack

- Vanilla HTML, CSS, JavaScript (no build tool, no framework, no npm)
- AnyChart v8 (CDN) for the sunburst visualization
- Python (parser only, not part of the Compass)
- Served locally via `python -m http.server`, deployed to a public FTP web server

## Project Structure

The repo has two independent parts:

- `compass/` — the web app (primary working area); see [compass/README.md](compass/README.md)
- `dataset/` — the Excel source file and Python parser that generate `data.json` and `source_ids.json`, plus `generate_seo_pages.py`; see [dataset/README.md](dataset/README.md)

Work almost exclusively happens in `compass/`.

## SEO landing pages

`compass/library/` (plus `sitemap.xml` / `robots.txt`) holds static, crawlable landing pages
deep-linking into the app, generated from the metric data by
`dataset/generate_seo_pages.py`.

**Rerun it whenever the metrics dataset changes** (i.e. after `parser.py`), then upload the
refreshed files — otherwise the pages drift from the catalogue.

## Changelog

After completing a task, decide whether it warrants a changelog entry:
- **Skip**: minor tweaks (CSS polish, wording, refactors, internal-only changes)
- **Combine**: several small related changes in one session → one entry
- **Add entry**: meaningful user-visible change (new feature, notable UI change, bug fix users would notice)

When an entry is warranted:

1. Update `CHANGELOG.md` at the repo root automatically — prepend a new entry (newest first).
2. For `compass/index.html` (`#changelogOverlay`) — **propose** the entry text to the user and wait for explicit approval before editing the file. The in-app changelog is end-user-facing and needs the user's sign-off. Add the approved item to the **bottom** of the `<ul>` for its month (append after the existing bullets), not the top.

Use today's date from the `currentDate` context variable. Match the existing entry format in each file. If `CHANGELOG.md` does not exist yet, create it with a `# Changelog` heading first.

## Conventions

- No emoji in code (existing emoji in filter labels are intentional; do not add new ones)
- JSON export schema (`compass/js/nextsteps.js` `exportJson()`): bump `schema_version` and update the import check in `compass/js/wizard.js` whenever the export format changes

## Branch Strategy

- `main` — stable, deployable branch
- `dev` — day-to-day working branch for simple changes
- feature branches (e.g. `add-comparison-step`) — for larger changes, branched off `dev`

## Forbidden
- Never edit `compass/data/data.json` or `compass/data/source_ids.json` directly — they are generated by `dataset/parser.py` and any manual edits will be overwritten on the next parser run
- Never edit `compass/library/`, `compass/sitemap.xml`, or `compass/robots.txt` directly — they are generated by `dataset/generate_seo_pages.py`; change the generator and rerun it
- Do not add external JS libraries or CSS beyond what is already loaded in `compass/index.html` without asking first
- Do not start `python -m http.server`, launch the app, or use run/verify skills to test UI changes — the user tests manually in their own browser. Implement the change and let them verify; don't ask for consent to do this, just skip self-testing by default.
- `node_modules/`, `dist/`, `build/`, `.git/`, `coverage/`
